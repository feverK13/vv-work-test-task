## Mock API wrapper

### Мета

Симулювати реальний бекенд: затримка + випадкові помилки, щоб виправдано показати skeleton/retry.

### Поведінка

- `mockFetch<T>(resolver: () => T): Promise<T>` — обгортка: random delay 300–800мс, ~20% chance reject з `Error`.
- Функції поверх неї: `fetchPartners()`, `fetchPartnerBySlug(slug)`, `fetchVacanciesByPartner(slug)`, `submitApplication(payload)`.
- Retry — кнопка "Спробувати ще" повторно викликає ту саму функцію. Без авто-retry/backoff — це MVP, зайва складність не потрібна.

### Edge cases

- `fetchPartnerBySlug` для неіснуючого slug → resolve з `null` (не reject) — це не мережева помилка, а "не знайдено", відповідно рендериться окремий стан, не retry-блок.

### Точки дотику

`api/mock-fetch.ts`, `api/partners.ts`, `api/vacancies.ts`, `data/*.ts`

### Мета

Заповнює прогалину брифу: немає явної сторінки "список усіх партнерів", а `/partners/:slug` — динамічна і потребує звідкись отримати slug. Рішення: короткий блок на Home з картками партнерів (3–6 шт. з mock-даних), кожна веде на свою `/partners/:slug`.

- Завантаження через `fetchPartners()` — skeleton (3–6 плейсхолдер-карток) під час завантаження, retry-блок при помилці.
- Картка: назва, короткий опис, CTA "Дивитись вакансії" → `/partners/:slug`.

## Категорії (Home)

### Рішення по неоднозначності брифу

Бриф: "клік по категорії фільтрує список на сторінці партнера" — але Home не прив'язаний до конкретного партнера. Рішення: клік по категорії веде на перший партнер зі списку (`partners[0].slug`) з query-параметром `?category=<id>`, який partner-сторінка читає і застосовує як активний фільтр при завантаженні. Явне відхилення від брифу — піде в README.

### Поведінка

- Chips з mock-категорій (Будівництво, Виробництво, Логістика, Готельно-ресторанна сфера, IT, Водії, Інші).
- Клік → `navigate('/partners/${firstPartnerSlug}?category=${id}')`.

### Точки дотику

`pages/home/categories-block.tsx`, `data/categories.ts`

## Partner-сторінка: інфо партнера

### Поведінка

- `fetchPartnerBySlug(slug)` при вході на сторінку.
- Loading → skeleton (заголовок + опис-плейсхолдери).
- Error (reject) → retry-блок.
- `null` (не знайдено) → окремий стан "Партнера не знайдено" + посилання на Home. НЕ retry-блок (це різні стани, не мережева помилка).
- Success → назва, опис, логотип партнера.

### Точки дотику

`pages/partner/partner-header.tsx`

## Partner-сторінка: список вакансій (завантаження)

### Поведінка

- `fetchVacanciesByPartner(slug)` паралельно з `fetchPartnerBySlug` (Promise.all або два незалежні хуки — не послідовно, щоб не подвоювати час очікування).
- Loading → skeleton-картки (4–6 шт.).
- Error → retry-блок, що повторює саме цей запит (не весь fetch партнера).
- Success + порожній масив → "У цього партнера поки немає вакансій" (не помилка).
- Query-параметр `?category=` з переходу з Home — застосовується як initial-значення фільтра категорії при першому рендері.

### Точки дотику

## Форма заявки

### Рішення по неоднозначності брифу

Поля форми (ім'я, телефон/telegram, повідомлення) — це відгук на вакансію, не загальний контакт. Один перевикористовуваний компонент `ApplicationForm` з опційним `vacancyTitle?: string`:

- На partner-сторінці: кнопка "Відгукнутись" на картці вакансії розгортає форму інлайн під карткою (без модалок — менше складності для MVP), `vacancyTitle` передається.
- На Контактах: та сама форма, без `vacancyTitle`, як загальне звернення.

### Поведінка

- Валідація на blur + при спробі сабміту: ім'я ≥2 символи, телефон/telegram — regex (формат: `+380XXXXXXXXX` або `@username`), повідомлення — опційне, ≤500 символів (лічильник символів).
- Помилки — інлайн під полем, без `alert()`.
- Сабміт: оптимістичний UI (форма одразу показує "Надіслано", ховається) + реальний виклик `submitApplication()` через mock-обгортку у фоні.
- Якщо mock-виклик у фоні впав з помилкою — показати ненав'язливе сповіщення "Не вдалось надіслати, спробуйте ще" з можливістю повторного сабміту (дані форми не втрачені).

### Edge cases

- Подвійний сабмiт (клік двічі швидко) — заблокувати кнопку на час запиту, попри оптимістичний UI.

### Точки дотику

`components/ui/application-form.tsx`, `hooks/use-form-validation.ts`, `utils/validators.ts`
